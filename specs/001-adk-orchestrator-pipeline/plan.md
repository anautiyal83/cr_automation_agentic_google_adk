# Implementation Plan: Google ADK Orchestrator Pipeline

**Branch**: `001-adk-orchestrator-pipeline` | **Date**: 2026-10-16 (revised 2026-11-02) | **Spec**: [spec.md](spec.md)

## Summary

Rewrite the CR Automation pipeline (now **NetConfig**) orchestration using Google ADK with a custom `PipelineAgent(BaseAgent)` that supports conditional backtracking for retry loops.

**As built (2026-11-02)**: 9 thin BaseAgent wrappers, one per skill package in `skills/`, mapped to 10 UI display steps. Milestones are built into PipelineAgent. QA skills analyze their own failures and set `_retry_target`. Control flow uses module-level dicts (`shared/state.py`) and on-disk error files, not ADK session state. NiceGUI UI ported from cr_automation-agentic. The original plan below (23 agents, `src/nodes/`, LlmAgent reviewers, cross-project imports) is kept as history and marked superseded where relevant.

## Technical Context

**Language/Version**: Python 3.11+ (agentic layer), Java 8 (JAR modules)

**Primary Dependencies**: google-adk 2.11.0, litellm, nicegui 2.0+, ruamel.yaml, pydantic 2.0+, openpyxl, xlsxwriter, aiosqlite

**Storage**: SQLite (pipeline.db) + file system (data/runs/)

**Testing**: pytest (unit + integration)

**Target Platform**: Windows/Linux server, browser UI at localhost:8000

**Project Type**: Web service (NiceGUI) + agent pipeline

**Performance Goals**: Full pipeline <10 min, milestone display <2s, 70%+ self-correction rate

**Constraints**: Must use ADK BaseAgent API; ~~must import existing agents from cr_automation-agentic~~ (superseded: all logic now in local skill packages, 5d3032c); ADK session state must not be used for inter-agent control flow (research R6)

### Phase 2: Custom PipelineAgent (Critical Path)
Replace SequentialAgent with backtracking-capable orchestrator.

| File | Action |
|------|--------|
| `orchestrator/pipeline_agent.py` | New — custom BaseAgent with state-machine loop |

Key design (as built): 9 agents indexed 0-8; `_RETRY_STEP_TO_INDEX` = {3→1, 4→1, 6→3, 8→6}; `_AGENT_MILESTONES` pause after agents for steps 4-9; cache check before cacheable agents. On each iteration: execute agent, publish events, milestone pause, then check `_retry_target` and jump if set (≤ MAX_RETRIES), else advance. *Original: 23 agents with conditional reviewers/routers — superseded by bd35015.*
