Azalio Autonomous Network Platform

From MOP and CIQ to a tested workflow

The Azalio Autonomous Network Platform reads a use case's documents, builds the CIQ validation rules and the cli-automation workflow with an LLM, and proves the workflow on a simulated network before anyone runs it on a real node. A person reviews the result after each stage.

  • 10 steps
  • 9 agents (Google ADK)
  • 7 review pauses
  • 3 retries per step, at most
  • 1 run at a time, the rest queue

The pipeline

Documents go in on the left; every step hands its output to the next. When a QA step finds a problem, the run goes back to the step that can fix it.

How the agents work together

The agents work in pairs: one makes something, the next one tests it and sends the problems back. An orchestrator runs them in order, and the developer answers questions and decides at every review.

What happens at a review pause

The run waits until someone with Update rights on Live Run decides. The pause survives a server restart.

ContinueAccept the step's output, even with QA findings, and go on to the next step.
Re-run stepGo back to the step that can fix the problem (shown by the dashed arrows) and run from there.
CancelEnd the run. It stays in Run History with everything it produced so far.

The system around it

One server runs the web app, the run queue and the pipeline. The pipeline calls out to the LLM, three Java tools and the simulator, and keeps everything it makes on disk.

How a workflow is proven (steps 8 and 9)

The workflow runs exactly as it would in production, through cli-automation, but against simulated nodes that answer with the real outputs from your session logs.
