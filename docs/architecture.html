F Pipeline Flow

23 agents execute sequentially. The PipelineAgent state machine supports conditional backtracking via _retry_target.

1 DOC Parser→ 2 DOC Analyzer→ 3 CIQ Config Gen→ M3→ 4 JSON Template→ M4→ 5 QA-Validation→ M5→ R5 Reviewer→ Router5→ 6 Workflow Gen→ M6→ 7 MOP Test→ M7→ R7 Reviewer→ Router7→ 8 Simulator Setup→ M8→ 9 Execution Test→ M9→ R9 Reviewer→ Router9→ 10 Final Report

R Self-Healing Feedback Loops

Three backtracking retry loops allow the pipeline to self-correct when QA or execution tests fail. Max 3 retries per loop before pipeline failure.

Loop A — Validation

Step 5 QA-Validation fails
↓ Reviewer analyzes test failures
↓ Router5 sets _retry_target=3
↓ Step 3 re-generates validation-rules.yaml
↓ Step 4 → Step 5 (re-test)

Loop B — MOP

Step 7 MOP Test fails
↓ Reviewer analyzes JAR parse errors
↓ Router7 sets _retry_target=6
↓ Step 6 re-generates workflow.yaml
↓ Step 7 (re-test)

Loop C — Execution

Step 9 Execution Test fails
↓ Reviewer classifies failure type
↓ Router9 routes to:
  • _retry_target=6 (workflow issue)
  • _retry_target=8 (simulator issue)

E Event System

X Cross-Project Integration

Step agents delegate to existing implementations in cr_automation-agentic via runtime import bridge.

Import Bridge (cr_import.py)

Uses importlib.util.spec_from_file_location with namespace isolation to avoid src package conflicts between the two projects.

Agent Delegation

Each StepNode._run_async_impl() calls _call_existing_agent() which instantiates the reference agent and invokes agent.execute().

State Mapping

ADK session state is transformed to/from the input_data / StepResult format expected by legacy agents.
